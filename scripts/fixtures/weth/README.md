# WETH fixture suite

Five EEST `blockchain_tests` JSON fixtures at network Prague, generated by
[`../gen-weth-fixtures.py`](../gen-weth-fixtures.py) and run by
[`../check-weth.sh`](../check-weth.sh). This is the arc's execution
evidence (`~/plans/non-vacuity.md`): every fixture's WETH account carries
`Blanc.wethCode` — the exact bytes `Blanc.wethCode_compile` witnesses as
`Prog.compile weth`'s output — as its `code`, and every expectation comes
from the pinned frozen EELS oracle's `t8n`, never hand-computed. Jaune's
fixture runner adjudicates: PASS means Jaune and the frozen oracle agree on
what those exact bytes do.

**Never hand-edit these files.** Regenerate with:

```sh
PYTHONPATH="$HOME/execution-specs/src" "$HOME/execution-specs/venv/bin/python" \
  scripts/gen-weth-fixtures.py
```

which requires the frozen oracle venv per `~/jaune/scripts/vectors/SOURCES.md`
and leaves `git diff --exit-code scripts/fixtures/weth/` clean on rerun
(confirmed byte-stable across independent runs).

## Cases

| file | case | what it exercises |
|---|---|---|
| `01-deposit.json` | `deposit()` | a plain-value call with empty data credits the caller's internal balance by the value sent (WETH's fallback function) |
| `02-withdraw.json` | `withdraw(wad)` | the caller's pre-set internal balance is decremented and the same amount of native ether is sent back |
| `03-transfer.json` | `transfer(dst, wad)` | purely internal accounting: `src`'s balance moves to `dst`, no native ether changes hands |
| `04-approve-transferFrom.json` | `approve` then `transferFrom` | two transactions in one block: the owner approves a spender, then the spender moves the owner's balance to a third address via the allowance path |
| `05-reentrancy.json` | adversarial `withdraw` re-entry | an attacker contract holding an internal WETH balance is triggered by an EOA and calls `withdraw(wad)`; Blanc's `withdraw` decrements storage *before* the external call (`sendToCaller`), which forwards only the fixed EVM value-transfer gas stipend (`sendToCaller` requests 0 gas explicitly). The attacker's code is identical on every entry — it always attempts `withdraw(wad)` again and ignores the result. This fixture asks the oracle what actually happens; the observed outcome (recorded in the step report) is a single successful withdrawal and no double-spend, matching what `Blanc.weth_preserves_solvent` proves in Lean |

Every case uses network Prague — the only fork both Jaune's supported lane and
the pinned oracle's `t8n` recognize (the pinned oracle has no Osaka) — and the
EEST `blockchain_tests` dialect, the only shape Jaune's fixture runner decodes.
Five Prague system predeploys (EIP-2935/4788/7002/7251/6110) are included in
every genesis alloc, copied verbatim from an EEST template fixture, because
`process_general_purpose_requests` requires two of them to carry code or the
whole block is invalid.

The reentrancy attacker's EVM bytecode is hand-authored directly in
[`gen-weth-fixtures.py`](../gen-weth-fixtures.py) (`attacker_bytecode`) — it is
the fixture's *input*, not an oracle-derived expectation, so hand-authoring it
is in scope (only filled *expectations* must come from the oracle, per the
plan's Fixed design decision 5). It is a minimal, unoptimized prop: build
`withdraw(wad)` calldata in memory, `CALL` the WETH address with it, ignore
the return value, `STOP`.

## Running

```sh
scripts/check-weth.sh
```

locates or builds the Jaune fixture runner (`lake build jaune/jaune`), runs
every file in this directory through it at `--network Prague`, and passes iff
every one does.
