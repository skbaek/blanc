# WETH10 differential scenarios

`manifest.json` is generated by `scripts/gen-weth10-differential.py` through
`scripts/check-weth10-differential.sh --write-manifest --manifest-only`.
`scripts/check-weth10-differential.sh --manifest-only` is the focused green
selector/endpoint/runtime-identity equality gate even while a behavioral row
is red.  The manifest is the
anti-vacuity inventory for the network-free deployed-vs-Blanc runner: every
row pins its endpoint owner, valid identity world, calldata digest, value,
compared channels, and semantic tags.  The checker regenerates this manifest
in memory and refuses any missing, orphaned, or stale row.

The deployed side executes the literal installed runtime from
`scripts/weth10-reference.json`; the Blanc side executes exact concrete
members of `Blanc.Weth10.weth10Code` emitted by
`scripts/eval-weth10-differential-code.lean`.  Both execute in the pinned EELS
Prague interpreter without network access.  Solidity storage and Blanc's
tagged storage are independently initialized and projected to logical
balances, nonces, allowances, and `flashMinted` before comparison.

This directory intentionally does not contain EEST blockchain-test goldens.
The differential gate is a live message-call comparison and therefore checks
return/revert bytes directly in addition to logical state, ETH balances, logs,
and callback-recorder storage.  The manifest's `explicitGaps` list is part of
the evidence and must remain truthful.

Callback-recorder storage fixes the child-visible calldata and state image on
successful rows.  A separate live opcode trace records every WETH10-originated
`CALL` and `STATICCALL`, including calls later erased by outer rollback; it
compares opcode, target, value, exact calldata (including its ABI word
placement), success, and returndata.  Unobservable caller-memory scratch
offsets remain an implementation freedom.  The permit rows therefore observe the exact precompile-1 input
and result rather than inferring `ecrecover` from the eventual allowance.

At the initial 6163-byte Blanc candidate the gate reported 101/104 agreement.
The three red rows were the same focused finding:
`approveAndCall`, `depositToAndCall`, and `transferAndCall` receive the exact
32-byte return word `2`.  The locked installed runtime succeeds and normalizes
it to encoded `true`; the initial Blanc candidate empty-reverted.  On
2026-08-08 the user adjudicated this conflict in favor of drop-in behavior:
zero returns canonical `false`, and every nonzero word returns canonical
`true`.  The matrix now checks both word `2` and the maximum 256-bit word at
all three callback endpoints.  There is no mismatch allowlist.

The current runtime identity and row count remain generated evidence, not
hand-maintained goldens.
