# Frozen legacy block producer API

`scripts/legacy_block_producer.py` is an **untrusted** Python producer. It
reconstructs legacy signed transaction RLP, status-receipt RLP, a 15-field
header and both tries, then renders Lean header/data/node-certificate/root
modules. Its consistency checks refuse bad input; only the Lean kernel's
checks establish the generated certificate equations. Input observation
adoption and chain validity remain outside this API.

Use `LegacyBlockSpec` to state an immutable capture identity and output names:

```python
from legacy_block_producer import LegacyBlockProducer, LegacyBlockSpec

producer = LegacyBlockProducer(LegacyBlockSpec(
    capture_sha256=(expected_capture_sha256,),
    number=expected_number,
    block_hash=expected_block_hash_without_0x,
    transaction_count=expected_count,
    namespace="Blanc.Lift.BlockWitness",
    module="Blanc.Lift.BlockWitness",
))
outputs, stats = producer.generate(capture_path)
# outputs maps relative .lean filenames to exact text; the caller owns writing.
canonical_capture = producer.reduced(capture_path)
```

The file digest must be explicitly expected. Number, hash, nonempty transaction
count and matching receipt count must agree. Transactions and receipts must
have legacy type `0x0`; receipts use status0/1. The supported header is the
original 15-field pre-London schema. Non-null later header fields, nonempty
ommers, typed transactions and typed receipts are refused. This is sufficient
for the existing schema; Amsterdam, typed transactions, later header formats
and empty-block rendering are not implemented.

`generate` reconstructs each transaction hash, the header hash and transaction
and receipt trie roots before rendering. It reads the capture and returns
text; it neither writes outputs nor invokes Lean. Output imports use `module`,
namespace declarations use `namespace`, and `chunk_bytes` controls node-proof
partitioning. The default documentation and generator tag are neutral; callers
may supply `header_doc` and `tag` for a retained instance's exact output text.

For an existing canonical transaction-byte literal, optionally pass
`references=(TransactionReference(...),)` in the spec. Each reference supplies
its transaction index, import module, Lean expression, exact `encoded` bytes,
documentation and mismatch diagnostic. The producer compares `encoded` with
the reconstructed signed transaction **before** reusing the Lean expression;
indices must be unique and in range. An optional `stats_label` adds that
transaction's and receipt's lengths to the result. With no references, all
transaction values are emitted directly and no observation module is imported.
The caller owns validating any named Lean reference against its source; a
Python byte comparison does not type-check that reference.

`scripts/weth9-creation-block-generate.py` remains the registered WETH9 CLI and
instance: frozen/reduced digests, block4,719,568, count137, slot85,
ObservationData literal extraction, exact old generated text, Binding exclusion,
reduction and output-directory/check/write policy stay there. Its normal
`--check` must still reproduce all ten committed generated modules exactly.
No capture, generated Lean source, binding or pin changed in this extraction.

The existing `weth9-creation-block-generated` gate fingerprints the neutral
engine explicitly in `scripts/gate-registry.json`. Its readable inventory is
regenerated by `python3 -B scripts/gate-cache.py inventory --output
docs/GATE_INPUTS.md`; the registry itself is hand-maintained input metadata.
Future Curve instances need their own reviewed captures, complete receipts,
instance wrappers and semantic tx/receipt bindings. This API does not adopt
those observations or supply those proofs. The frozen WETH9 data and its CLI
can be tagged/retired independently of the neutral engine.
