# Deployed-bytecode claim map: EIP-4788 beacon block root

## 5.14 EIP-4788 beacon block root: ring-buffer writes, tag-guarded reads and joint parent-root retention

EIP-4788's system contract at 0x000F3df6D732807Ef1319fB7B8bB8522d0Beac02 buffers beacon block roots in two
parallel 8,191-slot rings: timestamp tags at `t mod 8191` and root words at `8191 + (t mod 8191)`.
When `SYSTEM_ADDRESS` calls it at block opening, the 97-byte runtime `Blanc.beaconRootsCode` (`Blanc/SystemContracts.lean:35`)
ignores calldata length, writes the block's timestamp to `timeKey T` and `calldataload(0)` to `rootKey T`, and stops.
When any other caller enters, the bytes require 32 bytes of calldata, a nonzero query timestamp `t` and a matching tag
`storage[timeKey t] = t`, then return the 32-byte word at `rootKey t`; there is no `CALLVALUE` check and no age check.

Every execution-history statement below is at the covered forks (`CoveredFork`: Prague, Osaka, BPO1, BPO2); row R10
additionally states the protocol's own system call at Amsterdam.

## Disclosures and limits

81. **Reads accept ETH and failure modes are not classified.** The 97-byte runtime never inspects `CALLVALUE`, so a successful 32-byte non-system read accepts and retains any value carried into the frame (`r_s2`, `r_s6`). **Success is classified, failure is not**: rejected calls have no successful execution (`r_s2_control`), without distinguishing revert from out-of-gas or static faults.

82. **The mainnet root is an observation, not a deployment.** `r_s4` is rooted in `BeaconRootsCheckpointObservation` at block 22,431,083 (timestamp `1746612299`, header hash `0x28fb2c1d988435955e569451c6ad772f7fb5e61cddd7463c7b60e933ed5ff237`, state root `0xab350e0fe349aef68947ede26295f8946c34ce3af5e3ec76f4b26ddeef29c0e3`, canonical 97-byte runtime, and empty code at `SYSTEM_ADDRESS`). The values come from recorded public JSON-RPC reads; Lean does not authenticate them against consensus or a state trie.

83. **No transaction-level liveness.** `r_s7` proves fresh-frame execution at exact gas `readGas`. Sender balance, intrinsic transaction gas, access-list pricing and call forwarding are not claimed.

84. **Slot-grid overwrite control is an arithmetic mechanism control.** Constructing an 8,192-step concrete `JointRun` witness in Lean is out of reach, so `slot_grid_control` proves the overwrite mechanism directly over `writeAll` and `read` on any positive whole-second slot grid while `r_s8_time_control` supplies a full closed `KeptHistory` overwrite witness at `T + 8,191`.

85. **Multi-slot Phase 0 zero-`state_root` sentinel guard in `r_s9`.** Across two or more `process_slot` iterations, Phase 0's `process_slot` checks `latest_block_header.state_root == 0` on every slot; if filling an unfilled header hashed the beacon state to `0 : B256`, the next slot would overwrite `state_root` again. `FirstStepAnchorRoot` and `r_s9`'s consecutive-step clause state that exact single-slot or nonzero-digest guard rather than assuming SHA-256 preimage resistance. All `r_s9` equalities are chain-relative: no canonicality or finality is claimed.

86. **Amsterdam scope.** Amsterdam is covered only for the protocol system call (`r_s10`), where `RegularGasWithin` bounds regular gas by 30,000 and excludes state gas (`STORAGE_SET` charges draw from the system reservoir). User-frame gas and joint-chain rows stay on `CoveredFork` and Electra/Fulu.
