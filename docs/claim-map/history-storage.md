# Deployed-bytecode claim map: EIP-2935 historical block hashes

## 5.15 EIP-2935 historical block hashes: ring-buffer writes, window-guarded reads and block-hash retention

EIP-2935's system contract at 0x0000F90827F1C53a10cb7A02335B175320002935 stores recent parent block hashes in a
single 8,191-slot ring indexed modulo 8,191. When `SYSTEM_ADDRESS` calls it at block opening, the 83-byte runtime
`Blanc.historyStorageCode` (`Blanc/SystemContracts.lean:46`) ignores calldata length, writes `calldataload(0)` at
`key NUMBER = (NUMBER - 1) mod 8191`, and stops. When any other caller enters, the bytes require 32 bytes of calldata
and the 256-bit window guard `InWindow NUMBER q` (`q ≤ NUMBER - 1` and `NUMBER - q ≤ 8,191`), then return `storage[q mod 8191]`
with no presence tag and no `CALLVALUE` check.

Every execution-history statement below is at the covered forks (`CoveredFork`: Prague, Osaka, BPO1, BPO2); row H10
additionally states the protocol's own system call at Amsterdam.

## Disclosures and limits

87. **Reads accept ETH and failure modes are not classified.** The 83-byte runtime never inspects `CALLVALUE`, so a successful 32-byte non-system read accepts and retains any value carried into the frame (`h_s2`, `h_s6`). **Success is classified, failure is not**: rejected calls have no successful execution (`h_s2_control`), without distinguishing revert from out-of-gas or static faults.

88. **No presence tag on unwritten in-window slots.** Unlike EIP-4788, EIP-2935 stores only the hash word at `(NUMBER - 1) mod 8191` and checks only `InWindow NUMBER q`. Before 8,191 blocks have executed from a root, an in-window query for an earlier block number reads whatever word was already at `q mod 8191`, and `h_s8`'s third conjunct states that fact explicitly.

89. **The mainnet root is an observation, not a deployment.** `h_s4` is rooted in `HistoryStorageCheckpointObservation` at block 22,431,083 (timestamp `1746612299`, header hash `0x28fb2c1d988435955e569451c6ad772f7fb5e61cddd7463c7b60e933ed5ff237`, state root `0xab350e0fe349aef68947ede26295f8946c34ce3af5e3ec76f4b26ddeef29c0e3`, canonical 83-byte runtime, and empty code at `SYSTEM_ADDRESS`). Storage at the checkpoint is not read because no H statement claims pre-checkpoint slots. The values come from recorded public JSON-RPC reads; Lean does not authenticate them against consensus or a state trie.

90. **No transaction-level liveness.** `h_s7` proves fresh-frame execution at exact gas `readGas`. Sender balance, intrinsic transaction gas, access-list pricing and call forwarding are not claimed.

91. **Chain-relative block-hash identity.** `h_s9` equates an in-window read to `hdr.hash` on the supplied `KeptHistory`, and `h_s9_joint` equates the written slot to `latest_execution_payload_header.block_hash` on the supplied `RingJoint` run. Both statements are chain-relative: no canonicality or finality is claimed.

92. **Amsterdam scope.** Amsterdam is covered only for the protocol system call (`h_s10`), where `RegularGasWithin` bounds regular gas by 15,000 and excludes state gas (`STORAGE_SET` charges draw from the system reservoir). User-frame gas and joint-chain rows stay on `CoveredFork` and Electra/Fulu.
